Conbench¶

Conbench is a continuous benchmarking system for teams that need performance data to be easy to submit, inspect, compare, and act on.

The current Conbench system provides:

  • a Go server exposes a typed API over the existing Postgres schema,
  • a Svelte application provides the dashboard,
  • the conbench CLI is the supported write and CI workflow,
  • generated SDKs provide typed read and automation clients,
  • the legacy Flask application and old Python client stack are deleted from the maintained implementation.

Conbench keeps existing benchmark data by continuing to use the frozen Postgres schema. It does not keep the old API and Python package contracts as compatibility surfaces. Migration is handled through documented recipes, the Go CLI, generated SDKs, and targeted helpers only where real migrations prove they are needed.

What to do next¶

  • New users: start with the quickstart.
  • CLI users: use the CLI reference.
  • Benchmark authors: read submitting results.
  • CI owners: wire up CI reporting.
  • Dashboard users: review the dashboard screenshots.
  • Existing Conbench users: follow the Python app migration guide and legacy parity roadmap.
  • Package maintainers: use the legacy deprecation notices.
  • Operators: review operations.

Supported surfaces¶

Need Supported path
Submit benchmark results conbench results submit
Generate a PR or CI diagnostic conbench ci report
Manage scheduled regression alerts server-side alert rules plus conbench admin alerts evaluate and conbench admin alerts deliver
Browse trends and comparisons Svelte dashboard
Read/query from automation Generated SDKs and OpenAPI
Authenticate humans OIDC session login
Authenticate automation User-owned API tokens
Migrate legacy Python benchmark code JSON payloads plus Go CLI submission

The old Flask app, Jinja pages, password-login Python HTTP clients, and the benchalerts client package are retired surfaces, not ongoing maintenance targets. Generic webhook, Slack, GitHub Check, GitHub commit-comment, and email alert delivery are server-owned through the durable alert outbox. They are not a reason to retain legacy Python clients.
