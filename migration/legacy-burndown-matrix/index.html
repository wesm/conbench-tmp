Legacy Burndown Matrix¶

This matrix is the durable migration ledger for the retired Python/Flask implementation. A legacy surface can be removed only when its row is classified, the listed replacement checks pass, and the public docs tell users what to do. Ledger refs preserve the kata issues that originally tracked a row; they are traceability, not proof of an active blocker.

Decision values:

  • Replaced: new system has the supported path.
  • Retired: intentionally not carried forward.
  • Temporary: retained as a migration aid or reference.
  • Schema/reference: preserved because it defines data or golden behavior.

Deletion Rule¶

Do not delete a row's legacy files until:

  1. the decision is no longer temporary,
  2. missing product work is implemented or intentionally retired,
  3. verification evidence exists,
  4. the public docs tell users what to do,
  5. active CI, package, release, Docker, and deployment paths no longer reference the deleted surface.
